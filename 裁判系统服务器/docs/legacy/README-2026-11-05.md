# RoboMaster 裁判系统本地接收服务

## 当前结论

- Windows 已识别图传接收端：DJI `VID_2CA3/PID_1020`，对应 `COM5` 和 `COM8`。
- 实机测试中，`COM5` 持续输出以 `0x55` 开头的 DJI 私有 USB 数据；`COM8` 暂无上行数据。
- 公开裁判串口协议的帧头是 `0xA5`，默认参数为 `115200, 8N1`。血量由 `0x0003/0x0201` 提供，剩余弹丸和金币由 `0x0208` 提供。
- 图传接收端 USB-C 按官方手册用于向 RoboMaster Client 提供图像，并不是血量数据的公开串口出口。

## 一键启动

双击根目录的 `start_local_sim.bat`。**默认启动完整链路，但不碰 Wi-Fi/ICS**：
赛事服务/裁判系统 → 图传 daemon → 官方选手端 → 自定义客户端。它会：

1. 停掉本机旧的 `RoboMasterEngine` / `RMServer` / `AdapterSvrS0` / 日志端 / Redis；
2. 检查 UDP `62101/62102/62103` 是否可绑定；默认**不停 ICS**。如果端口被热点占用，
   脚本会拒绝动手并提示你先关闭移动热点；
3. 确保 `192.168.1.2/32` 和 `192.168.1.3/32` 挂在 VMware VMnet1（或其它已启用的
   非 Wi-Fi 虚拟网卡）上，供引擎和官方选手端使用；
4. 启动 InfluxDB 和 `RoboMasterEngine`（引擎自动拉起 RMServer/AdapterSvr/日志端/Redis）；
5. 默认跳过 `Local` 热点；只有显式 `-WithHotspot` 才启动热点和 `192.168.137.1`；
6. 启动 `RMClientDaemon` → 官方选手端 → WSL 自定义客户端（直接拉起
   `~/rm26-build/RoboMasterClient2025`，不经过 run.sh）；
7. 打印进程、端口、引擎连接、官方选手端登录和日志端状态。

只起赛事服务（不启动客户端）：

```bat
start_local_sim.bat -ServicesOnly
```

物理机器人需要连 `Local` 热点时：

```bat
start_local_sim.bat -WithHotspot
```

此模式会短暂断开 Wi-Fi（Wi-Fi 和热点共用 Intel BE201 射频）。热点参数为
`Local / 12345678 / 2.4 GHz / WPA2`；`192.168.1.2` 仍留在 VMnet1 上，不再加到热点网卡。

> 外部裁判系统（例如 `cpxt` 局域网）正在使用时不要双击本机模拟器：它会把这台电脑变成 `192.168.1.2` 的赛事服务器。

完整可复现步骤、本次成功记录和排障表见 **[重启链路.md](重启链路.md)**。

## 真实血量数据的两条接入路径

### 官方赛事引擎局域网

1. 使用只开启 2.4 GHz、带 LAN 口的路由器，路由器地址设为 `192.168.1.1/24`，开启 DHCP 和 WPA2。
2. 服务器电脑通过网线接路由器 LAN 口，将该网卡静态地址设为 `192.168.1.2/24`。
3. 启动现有 `RoboMasterEngine.exe`。官方手册说明它会自动启动赛事引擎服务器。
4. 在主控模块的 Wi-Fi 设置中连接该路由器。连接成功后，在赛事引擎 UI 中查看机器人状态。

当前电脑没有连接中的有线网卡，只有地址为 `172.20.10.3` 的 Wi-Fi，因此现在尚不满足这条链路的 `192.168.1.2/24` 条件。

### 主控 UART 直连

将裁判系统主控模块公开 UART 数据口通过合适电平的 USB 转串口设备接到电脑，参数设为 `115200, 8N1`，再把新增的 COM 口传给本服务。这条路径可由本服务直接解出公开协议数据。

不要把图传发送端的遥控 UART 当作裁判数据 UART。图传手册中的该接口是 `921600, 8N1`，输出 21 字节遥控帧，帧头为 `0xA9 0x53`。
