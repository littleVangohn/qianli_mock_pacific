# 电控组最小数据对接文档





## **0\. 链路与封装**

- 电控通过**图传模块发射端（VT03/VT13）的 UART** 发送 0x0310，**不经过裁判系统主控**。
- 物理链路：电控 UART TX → 图传发射端 UART（921600，与 21 字节遥控/键鼠帧同一路）→ 图传无线链路 → 图传接收端 USB-C → 官方选手端 RoboMasterClient.exe → MQTT topic `CustomByteBlock`。
- 0x0310 单帧 payload 为定长 150 字节（初始协议）或 300 字节（V1.3），频率上限 50 Hz；本文第 5 节的 11 字节应用负载放在 payload 的前 11 字节。
- 客户端按首字节魔数 `0x5A` 识别状态包；payload 长度、尾部填充和同通道的视频分片都不影响识别。
- 裁判系统主控模块 MC02 只负责供电、机器人 ID 和图传对频，不在 0x0310 数据路径上。

## **1\. 公共编码与有效性约定**

- 角度统一使用 `int16`，单位 **`0.0001 rad`**。

- **编码：** `encoded = round(rad × 10000)`

- **客户端解码：** `rad = encoded / 10000.0`

- **角度显示：** `deg = rad × 180 / π`

- 偏航角统一归一化到 `[-pi, pi)` 后编码；整数编码范围约 `[-31416, 31416]`，不会超出 `int16`。

- 多字节整数使用小端序。

- 包首字节固定 `0x5A`（魔数），第 2 字节固定 `0x01`（版本）。客户端用魔数识别本包，你不需要额外加长度字段或包头。

- `seq` 是状态包序号，每发一个新状态包加一，`255` 后回绕到 `0`。

- 客户端只在收到新 `seq` 时更新状态和本机接收时间；重复包和乱序旧包不得刷新接收时间。

- 连续 `300 ms` 没有收到新 `seq` 时，客户端将整包判定为通信超时：保留最后显示值，UI 变灰并标为失联。

- `pose_valid` 和 `pitch_valid` 表示数据源本身是否可信，不能被通信超时判断替代。最终可用条件为"状态包未超时，并且对应有效位为 `1`"。

- 连续状态通信只保留最新包，不得在链路恢复后补发积压的历史状态包。

示例：`barrel_pitch = 0.1234 rad` 时发送整数 `1234`；`barrel_pitch = -0.4700 rad` 时发送整数 `-4700`。

## **6\. 模块 E4：自定义客户端键位与上行控制**

**方向：我们 → 电控（上行）。** 自定义客户端捕获键鼠，经官方选手端、图传链路，以官方标准 21 字节遥控帧下发到车上。本节只讲键位和帧；0x0310 是电控→我们的状态包（第 2–5 节），不在这里。

### 6.1 链路

```text
自定义客户端 捕获键鼠
  → MQTT KeyboardMouseControl（protobuf，QoS 1，不等 ACK）
  → 官方选手端 RoboMasterClient.exe
  → 图传接收端 USB-C（操作手侧）
  → 图传无线链路
  → 图传发射端 VT03/VT13（车上）
  → UART 921600 8N1（与 0x0310 同一条线，反方向）
  → 电控主控
```

- 客户端**只发 MQTT**，不拼 21 字节帧；帧由官方选手端/图传发射端生成。
- 发射端每 **14 ms** 输出一帧（约 71 Hz），空闲也发，键鼠字段为 0。
- 上行 0x0310 与下行 21 字节帧是全双工两个方向，互不排队。
- **不重传、不等 ACK**；链路抖动会静默丢帧，电控必须自己做失联保护（见 6.5）。

### 6.2 改绑后的键位

官方遥控帧只认下面 16 个键。**车控功能全部落在官方键上**，不再使用 Space/T/↑↓/右 Shift 这类帧外键：

| 操作 | 按键 | 官方位 | 语义 |
|---|---|---|---|
| 底盘前进 / 后退 | W / S | bit0 / bit1 | 电平，按住有效 |
| 底盘左移 / 右移 | A / D | bit2 / bit3 | 电平，按住有效 |
| 加速 | 左 Shift | bit4 | 电平；右 Shift 同一位，不要用 |
| 制动 | **R** | bit8 | 电平，按住刹车 |
| 自动吊射开关 | **E** | bit7 | 上升沿切换开/关 |
| 换弹种 17↔42 | **X** | bit12 | 上升沿切换 |
| 跟随 ↔ 小陀螺 | G | bit10 | 上升沿切换 |
| 小陀螺左旋 / 右旋 | C / V | bit13 / bit14 | 上升沿启停 |
| 开火 | 鼠标左键 | `left_button` | 电平，按住=持续请求 |
| 云台左右 | 鼠标水平 | `mouse_x` | 增量，右正 |
| 炮管俯仰 | 鼠标垂直 | `mouse_y` | 增量，上/前正 |
| 共享标点 | 鼠标中键 | `mid_button` | 按键会带，车控可忽略 |
| 视角 / 面板 | 1/2/3、P、Tab、~、M、O、I、K、H、F12、Esc | 无 | 纯本地，不进帧 |

> 改绑前后：Space→R，T→E，右 Shift→X；↑/↓ 取消，炮管俯仰只用鼠标 Y。F 仍是本地飞镖面板，Q 仍是本地调试，B 在大地图打开时是本地标记键——这三个键的位电控一律忽略。
>
> 为什么这样选：制动不用 Ctrl（Ctrl 是客户端快捷键修饰键，Ctrl+1/2、Ctrl+T 有本地功能，按住刹车容易误触）；换弹不用 B（大地图打开时 B 是本地标记键）；右 Shift 与左 Shift 共用 bit4，按右 Shift 会被当成加速；↑/↓ 与鼠标 Y 重复。

**16 位 `keyboard_value` 逐位定义**：

| bit | 键 | 我们的用途 | 电控处理 |
|---|---|---|---|
| 0 | W | 前进 | 按住前进 |
| 1 | S | 后退 | 按住后退 |
| 2 | A | 左移 | 按住左移 |
| 3 | D | 右移 | 按住右移 |
| 4 | Shift | 加速（左右 Shift 同一位） | 按住加速；操作手只用左 Shift |
| 5 | Ctrl | 客户端快捷键修饰键 | 忽略 |
| 6 | Q | 客户端本地调试 | 忽略 |
| 7 | E | 自动吊射 | 上升沿切换 |
| 8 | R | 制动 | 按住刹车 |
| 9 | F | 本地飞镖面板，按住时置位 | 忽略 |
| 10 | G | 跟随 ↔ 小陀螺 | 上升沿切换 |
| 11 | Z | 空闲 | 保留 |
| 12 | X | 换弹种 | 上升沿切换 |
| 13 | C | 小陀螺左旋 | 上升沿启停 |
| 14 | V | 小陀螺右旋 | 上升沿启停 |
| 15 | B | 大地图本地标记；其余时候空闲 | 忽略 |

> 官方 16 键本来就在客户端的转发表里；这次只是把功能改绑到 R/E/X，**不需要改 MQTT 或帧格式**。F/Q/B 的本地面板动作不影响 R/E/X。客户端侧只需同步帮助页和 README 的键位提示。

### 6.3 21 字节帧里我们负责的字段

整帧 21 字节，`921600 8N1`，`header = A9 53`，CRC-16/CCITT-FALSE（多项式 `0x1021`，初值 `0xFFFF`，不取反、不异或；覆盖范围以官方示例代码为准）。

| 字段 | 位置 | 类型 | 来源 | 说明 |
|---|---|---|---|---|
| `header0/1` | Byte0 / Byte1 | — | 发射端 | `0xA9` / `0x53` |
| `ch0–ch3` | bit16 / 27 / 38 / 49 | 11 bit | 发射端 | 右横 / 右纵 / 左纵 / 左横；本客户端不设置 |
| `mode_switch` | bit60 | 2 bit | 发射端 | 拨杆 `0=C, 1=N, 2=S` |
| `pause_button` | bit62 | 1 bit | 发射端 | 暂停 |
| `custom_button_left/right` | bit63 / bit64 | 1 bit | 发射端 | 自定义键 |
| `dial` | bit65 | 11 bit | 发射端 | 拨轮 |
| `trigger` | bit76 | 1 bit | 发射端 | 扳机 |
| `mouse_x` | Byte10–11 | int16 LE | **本客户端** | 水平增量，右正 |
| `mouse_y` | Byte12–13 | int16 LE | **本客户端** | 垂直增量，上/前正 |
| `mouse_z` | Byte14–15 | int16 LE | **本客户端** | 滚轮增量，上正；本键位不用 |
| `left/right/mid_button` | Byte16 bit0–5 | 2 bit each | **本客户端** | 电平，不能按整字节判 0/1 |
| `keyboard_value` | Byte17–18 | uint16 LE | **本客户端** | 16 位掩码，见 6.2 |
| `crc16` | Byte19–20 | uint16 LE | 发射端 | CCITT-FALSE |

> 没有物理遥控器时，发射端的 ch0–ch3 / 拨杆 / 拨轮 / 扳机一般是中位或默认值；电控不要把它们当成我们客户端的控制量。

### 6.4 客户端实际发送行为

| 项 | 行为 | 电控要不要再处理 |
|---|---|---|
| 鼠标灵敏度 | 客户端 0–100，默认 50 = ×1.0，范围 ×0.1–×3.0；发送前已乘好 | **不要再乘系数** |
| 鼠标量程 | 单帧累积钳在 ±32767 | 不需要 |
| `mouse_x` | 右为正，本帧增量 | 按增量用，不要跨帧累加 |
| `mouse_y` | 上/前为正；屏幕向下为负 | 按官方语义用 |
| `mouse_z` | 滚轮向上为正，每格约 +120；快速滚动会在 13 ms 内累加 | 本键位不用，可忽略 |
| `keyboard_value` | 电平（按住=1），不是事件 | R 按住有效；E/X/G/C/V 自己取上升沿 |
| 发送节奏 | 有活动时按 13 ms（约 75 Hz）最小间隔冲刷；静止不发 | 收到一帧代表当前状态，不要等固定周期 |
| 松手 | 发一帧全零（中性帧）后停止 | 全零=松开，不是断线 |
| 面板/弹窗 | 设置/兑换/补给/Tab/伤害/大地图/帮助等打开时，先发一帧全零，然后暂停发送 | 期间收不到新帧属正常 |
| 送达 | QoS 1，但不等 ACK、不重传 | 必须自己做失联保护 |
| 开火 | 左键是**电平**（按住=持续请求） | 电控按热量/弹量/摩擦轮闭锁，状态包回传 `fire_permitted` |

- 客户端只在**已登录（选车）、非战术模式、无阻挡面板**时捕获键鼠；其他情况一律不发，并补中性帧。
- 右 Shift 仍会置 bit4：操作手不要用右 Shift 换弹，换弹只用 X。
- 官方选手端内部还有上行限频，超过阈值会静默丢弃；现场以发射端 UART 抓帧为准。

### 6.5 电控侧处理顺序

1. 校验 `header0 == 0xA9`、`header1 == 0x53`、长度 21、`crc16`；坏帧直接丢，不用坏帧刷新状态。
2. **电平键**：W/S/A/D/Shift/R 按住有效。R 是制动，松开即解除；W/S/A/D 松开即零速。R 与 W/S/A/D 同时按下时，制动优先。
3. **上升沿键**：G、C、V、E、X。只在键位从 0→1 的那一帧触发一次；不要按“这一帧是 1”反复触发。
4. G 上升沿：在 `1=跟随` 和 `2=小陀螺` 之间切换；切换时**清掉自旋状态**。C/V 只在 `2=小陀螺` 下有效：C 启动/停止左旋，V 启动/停止右旋；按另一个键直接反向。保护模式 `3` 下忽略 C/V/G。
5. E 上升沿：自动吊射开/关取反；实际状态用 0x0310 的 `auto_lob_active` 回传。X 上升沿：弹种 17↔42 取反；状态由电控保持，0x0310 暂无弹种字段，UI 如需回显再约定保留位。E/X 是切换命令，客户端重启后操作手各按一次让两边状态对齐；失联保护触发时，E/X 状态复位到默认（自动吊射关、17 弹）。
6. 鼠标增量每帧只消费一次，不跨帧累加；不要再乘灵敏度。
7. 左键是开火请求，不是“按下沿=一发”；单发/连发/射频、热量、弹量、摩擦轮、枪口状态都由电控按规则闭锁，并在 0x0310 状态包回传 `fire_permitted`。
8. **失联保护**：发射端 UART 每 14 ms 都有一帧，“没有帧”只能说明图传/串口断了，不能说明客户端还在。请现场实测“客户端停止发布后，发射端是保持最后键鼠值还是清零”：
   - 若清零：连续 300 ms 键鼠全零即可停机（同时覆盖松手和面板打开）。
   - 若保持最后值：必须加心跳（客户端定期翻转一个保留位，或走 `CustomControl` 带序号），电控 300 ms 无心跳就清零驱动、发射和 C/V 自旋锁存。仅靠全零帧覆盖不了“按住 W 时客户端崩溃”。
9. 忽略位：bit5 Ctrl、bit6 Q、bit9 F、bit15 B；bit11 Z 保留。本客户端不设置的字段（ch0–ch3、`mode_switch`、`pause_button`、`custom_button_*`、`dial`、`trigger`）按中性值处理；只有车上另接物理遥控器时才使用。

### 6.6 自测

- 客户端侧：`RM_KEYBOARD_MOUSE_TRACE=1` 启动，日志出现 `[keyboard-mouse-trace] stage=flush` 且 `keyboardMask=` 随按键变化。
- 按键自检：按 W/Shift/E/R/G/X/C/V，看掩码 bit0/4/7/8/10/12/13/14；按 Space/T/↑/↓ 掩码**不应变化**（这些键已取消）；按右 Shift 只会置 bit4（与左 Shift 无法区分），不要用。
- 面板自检：打开设置/兑换/补给等面板，应先看到一帧全零，然后不再刷新。
- 电控侧：发射端 UART 抓帧，按住 W 看 Byte17 bit0；按住 R 看 bit8；按 E/X/G/C/V 看是否只在上升沿动作；松手看是否收到一帧全零；移动鼠标看 `mouse_x` 符号。

## **7\. 客户端处理顺序**

1. 检查首字节是否为魔数 `0x5A`，以及长度是否够 11 字节。

2. 检查 `seq`，丢弃重复包和乱序旧包。

3. 对新包更新三个角度、机构状态和本机最后接收时间。

4. 距离最后一个新包超过 `300 ms` 时，将整包数据标记为通信超时。

5. 未超时时，分别结合 `pose_valid` 和 `pitch_valid` 判断姿态角与俯仰角能否使用。
