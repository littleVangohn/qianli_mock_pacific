# 机械臂通信协议（电控 / 自定义控制器 ↔ 客户端 ↔ 下位机主控）

客户端在机械臂链路上只做两件事：

1. 按 Z 切换模式，把 18 字节模式帧发到 `0x0311`，同时写回自定义控制器（RS-232）。
2. 自定义控制状态下，把 RS-232 收到的最新 position 按 50 Hz 持续发到 `0x0311`。

本文给电控两边的解析/发送格式。上行状态包、键鼠帧见仓库 README。

## 1. 客户端 → 下位机主控（0x0311）

- Topic：`CustomControl`，protobuf `bytes data = 1`，QoS 1，不等 ACK。
- `0x0311` 单条 `data` 上限 **30 字节**，频率上限 **75 Hz**（每辆车链路独立）。
- `data` 固定为 **18 字节 position**，客户端按 **50 Hz 持续发送**：
  - 视觉自动控制：关节角全 0，`relative_time = 0x7FFFFFFF`。
  - 自定义控制：串口最新 position 原样转发，`relative_time` 由自定义控制器填。
- 视觉自动状态下也会持续发，所以模式是确定的，不依赖某一帧是否丢包。

### 18 字节 position（packed、小端，无填充）

| 偏移 | 类型 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0–13 | `uint16_t[7]` | `joint_angle[7]` | 7 个关节角，客户端不解释单位 |
| 14–17 | `uint32_t` | `relative_time` | 模式/相对时间，见下 |

`relative_time` 取值：

| 值 | 含义 |
| --- | --- |
| `0` | 自定义控制（模式帧） |
| `0x7FFFFFFF`（`INT_MAX`，**不是** `0xFFFFFFFF`） | 视觉自动控制（模式帧） |
| 其他 | 自定义控制状态下，自定义控制器自己的相对时间；客户端原样转发 |

- `joint_angle` 的单位、零位、方向由电控/机械自行约定，两端一致即可。
- **模式帧的关节角一律为 0**，主控只按 `relative_time` 切状态，不要用模式帧的角度驱动机械臂。
- 自定义控制器自己的时间戳要避开 `0` 和 `0x7FFFFFFF`（这两个值被模式帧占用），
  建议从 1 开始递增。

## 2. Z 切换

按 Z 是点击切换（不是按住）：

| 当前状态 | 按下 Z 后 | 立刻发出的模式帧 |
| --- | --- | --- |
| 视觉自动 | 自定义控制 | `relative_time = 0` |
| 自定义控制 | 视觉自动 | `relative_time = 0x7FFFFFFF` |

- 切换帧同时走两条路：`0x0311` 发给下位机主控；RS-232 写回自定义控制器
  （裸 18 字节 position，连写 3 帧防串口误码）。
- 切换后由 50 Hz 定时器持续发送当前模式，不需要主控再确认。
- 客户端不接受在 broker 断开时切换，避免本地状态和车端脱节。

## 3. 客户端 ↔ 自定义控制器（RS-232）

自定义控制器通过 USB-RS232 直连上位机，两个方向的帧格式不同：

- 控制器 → 客户端：**34 字节定长帧**（16 字节通信头 + 18 字节 position）。
- 客户端 → 控制器：**裸 18 字节 position**，只在 Z 切换后连发 3 帧，用于确认模式。

### 3.1 控制器 → 客户端（34 字节）

```text
偏移   0                16                          34
       |---- 16 B 头 ----|------ position 18 B ------|
```

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0–15 | 16 B | 通信头；客户端接收时忽略（可约定内容） |
| 16–33 | 18 B | `position`：7 × uint16 关节角（16–29）+ uint32 relative_time（30–33） |

`position` 就是上面定义的那个 18 字节结构，**不是 34 字节**；34 是整条串口帧的长度，
`position[34:16]` 表示 position 占整帧的第 16 字节到第 34 字节（左闭右开，即
`[16, 34)`，共 18 字节）。注意 `sizeof(struct position)` 在默认对齐的 C 编译器里是
20 字节（`uint32` 前多了 2 字节填充），串口收发的必须是紧凑的 18 字节，建议按字节
手工拼包，不要直接 `memcpy` 整个结构体。

- 串口 8N1、无流控；端口和波特率由客户端环境变量配置（`RM_ARM_SERIAL_PORT`、
  `RM_ARM_SERIAL_BAUD`，默认 115200）。
- RS-232 是全双工点对点：客户端发模式帧和控制器发 position 可以同时进行，
  没有半双工收发切换/总线争用问题，两边都按整帧连续发送即可。
- 建议在 16 字节通信头的第 0 字节固定一个魔数（例如 `0xA5`），客户端用
  `RM_ARM_SERIAL_MAGIC=0xA5` 打开帧头重同步，避免客户端从半帧开始接收后永久错位。
  不配魔数时客户端按固定 34 字节切帧，要求控制器从串口打开起一直整帧对齐发送。
- 客户端按固定 34 字节切帧，不做转义、不加分隔符；控制器必须连续发满 34 字节。
- 自定义控制状态下，控制器持续发 position（建议 ≥50 Hz），客户端只保留最新一帧并
  按 50 Hz 转发；无需等客户端确认。
- 视觉自动状态下客户端只缓存 position、不转发到 `0x0311`。

### 3.2 客户端 → 控制器（18 字节）

Z 切换后立即回发 3 帧裸 18 字节 position（没有 16 字节通信头）：

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0–13 | 14 B | `joint_angle[7]`，固定全 0 |
| 14–17 | 4 B | `relative_time`：`0` = 已切到自定义控制；`0x7FFFFFFF` = 已切到视觉自动控制 |

- 控制器收到 18 字节整帧即视为一次模式确认，只看 `relative_time`，不要用关节角。
- 该方向只在切换瞬间发送，不参与控制器 → 客户端的 34 字节定长切帧，两个方向互不影响。

## 4. 失联保护

- 自定义控制状态下，如果串口超过 300 ms 没有新 position，客户端只在日志里打
  `RM26_ARM_POSITION_STALE`，**不会替电控切换状态**，并且继续按 50 Hz 重发最后一帧。
- 因此最后一帧的 `relative_time` 会停止前进。**主控应把 `relative_time` 不再变化
  （或超过约定阈值）判为失联，停止机械臂运动并保持当前姿态。**
- MQTT 是 QoS 1 但不等 ACK，链路抖动会静默丢帧；即使客户端在持续发，主控也要做
  帧间隔超时保护。

## 5. 和同通道其他消息的区分

`CustomControl`（`0x0311`）上目前有两类数据，主控按**长度**分流：

| 长度 | 来源 | 处理 |
| --- | --- | --- |
| 10 B | 前哨站状态，`data[0] = 0x01` | 按 README 前哨站格式解析 |
| 18 B | 机械臂 position | 按本文解析 |

频率预算：前哨站 10 Hz + 机械臂 50 Hz = 60 Hz，低于 75 Hz 上限。

## 6. 解析示例

C（显式按小端拼，不依赖结构体 packing）：

```c
static inline uint16_t rd_u16le(const uint8_t *p) {
  return (uint16_t)(p[0] | (p[1] << 8));
}
static inline uint32_t rd_u32le(const uint8_t *p) {
  return (uint32_t)p[0] | ((uint32_t)p[1] << 8) |
         ((uint32_t)p[2] << 16) | ((uint32_t)p[3] << 24);
}

void on_custom_control(const uint8_t *data, uint16_t len) {
  if (len != 18) return;              /* 10 = 前哨站，其余忽略 */
  uint16_t joint[7];
  for (int i = 0; i < 7; ++i) joint[i] = rd_u16le(data + i * 2);
  uint32_t rt = rd_u32le(data + 14);

  if (rt == 0x7FFFFFFFu) {
    arm_set_mode(VISION_AUTO);        /* 角度全 0，不要驱动 */
  } else if (rt == 0u) {
    arm_set_mode(CUSTOM_CONTROL);     /* 角度全 0，不要驱动 */
  } else {
    arm_set_mode(CUSTOM_CONTROL);
    arm_apply_joint(joint);           /* 自定义控制器的真实姿态 */
    arm_note_relative_time(rt);       /* 用它的推进判断数据新鲜度 */
  }
}
```

Python（自定义控制器侧，组 34 字节上行帧）：

```python
import struct

def build_uplink(joint, relative_time, header16=b'\x00' * 16):
    # 16 字节通信头客户端会忽略；position 在 [16:34)
    return header16 + struct.pack('<7HI', *joint, relative_time)

# 客户端发下来的模式确认是裸 18 字节 position，没有 16 字节头
def parse_client_frame(frame: bytes):
    assert len(frame) == 18
    joint = struct.unpack_from('<7H', frame, 0)
    rt, = struct.unpack_from('<I', frame, 14)
    return joint, rt   # rt == 0 自定义控制；rt == 0x7FFFFFFF 视觉自动
```

## 7. 需要电控确认的事项

1. RS-232 波特率（客户端默认 115200，可用 `RM_ARM_SERIAL_BAUD` 改）。
2. 控制器 → 客户端的 34 字节帧前 16 字节通信头是否需要特定内容（客户端接收时忽略）。
   客户端 → 控制器方向只发裸 18 字节 position，不带头；如果这个方向也要加头，
   告诉客户端。
3. 自定义控制器 position 的发送频率，以及 `relative_time` 是否每帧推进
   （主控靠它判新鲜度；不要使用 `0` 和 `0x7FFFFFFF`）。
4. 主控的失联阈值（建议 300 ms），以及失联时保持姿态还是回零。
5. `joint_angle` 的单位/零位/正方向。
