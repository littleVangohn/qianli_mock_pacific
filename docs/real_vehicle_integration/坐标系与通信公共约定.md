# 坐标系与最小通信约定

## 1. 统一坐标系

### 1.1 世界坐标系 F

- 原点：未镜像赛场图红方侧左下角。
- `+X_F`：红方基地指向蓝方基地，地图左向右。
- `+Y_F`：地图下向上。
- `+Z_F`：竖直向上。
- 偏航 `0°` 指向 `+X_F`；从上向下看逆时针为正。
- 角度范围统一为 `[-180°, 180°)`。
- 红蓝双方使用同一坐标，蓝方镜像只发生在 UI 层。

若裁判系统原始坐标与此不同，仅在裁判数据适配层转换一次。联调时必须用两个已知场地点确认 X/Y 方向，不能只在原点测试。

### 1.2 底盘坐标系 B

- `+X_B`：车头正前方。
- `+Y_B`：车辆左侧。
- `+Z_B`：车辆上方。

### 1.3 云台和炮管

- 云台偏角 `gimbal_offset_yaw`：相对底盘，向车辆左侧转为正。
- 炮管俯仰 `barrel_pitch`：水平为 `0°`，抬炮为正，压炮为负。
- 云台世界正方向 `gimbal_yaw`：云台相对世界 `+X_F` 的角度。

唯一需要的姿态关系：

```text
chassis_yaw = wrap(gimbal_yaw - gimbal_offset_yaw)
chassis_in_gimbal_ui = wrap(-gimbal_offset_yaw)
```

UI 不要求电控再发送 `chassis_yaw`，底盘世界角由客户端本地推导，避免重复数据。

### 1.4 图像坐标

- 原点：图像左上角。
- `u` 向右，`v` 向下。
- 发给客户端的点和框统一归一化到 `[0,1]`，不随分辨率变化。

## 2. 最小协议规则

- 角度使用 `int16`，单位 `0.0001 rad`（`encoded = round(rad × 10000)`；显示时换算成角度 `deg = rad × 180 / pi`）。
- 百分比使用 `uint8`，范围 `0–100`；UI 不需要 0.1% 精度。
- 图像归一化坐标使用 `uint16`，`0–65535` 映射到 `0–1`。
- 多字节整数统一小端序。
- 通过版本、序号和有效位区分协议、丢包和无效数据。
- MQTT/TCP 链路已有完整性校验时，不在每个小包重复增加 CRC；若底层要求 CRC，则服从底层协议。
- 不为 UI 未使用的数据预留高频字段；新增字段必须说明对应哪个 UI 模块。

## 3. 最小包头

连续状态包只需要：

| 字段 | 大小 | 说明 |
|---|---:|---|
| `version` | 1 B | 协议版本 |
| `seq` | 1 B | 包序号，允许回绕 |

客户端以本机接收时间计算数据年龄，因此基础包不强制携带时间戳。只有视觉需要把结果和视频帧严格对齐时，才在视觉包中增加帧号或时间戳。

## 4. 发送频率

| 数据 | 频率 |
|---|---:|
| 三个姿态角 | 20 Hz |
| 模式、机构 | 状态变化立即发送；否则随姿态包携带 |
| 视觉目标 | 有目标时 10–20 Hz；无目标时 2 Hz 或仅变化发送 |
| 静态标定参数 | 不走实时链路 |
| 控制命令 | 30–50 Hz，空闲时降低到心跳频率 |

客户端对 20 Hz 姿态进行插值显示，不需要为了 60 FPS UI 把链路提高到 60 Hz。

## 5. 数据失效

- 连续 300 ms 没有新序号：UI 变灰并标为失联。
- 无效位为 0：保持最后显示值但变灰，不能用 0 代替无效。
- 控制链路超时值由电控安全策略确定，建议 200–300 ms 后安全清零。
- 重新连接先发一个完整基础状态包。

## 6. 禁止发送

- 原始视频、辅助相机视频。
- 雷达点云和完整视觉候选框列表。
- 底盘世界角等可由现有字段推导的数据。
- A/D 预测轨迹点列和弹道轨迹点列。
- 高频字符串、调试日志和重复的裁判系统数据。
